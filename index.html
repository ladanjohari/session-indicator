Session Indicator — a native macOS menu bar component for AI agent supervision

When multiple AI agents run in parallel, developers lose awareness. The Session Indicator restores it — without interrupting focus.

Five states. No learning curve.

Idle
No active agent. Dot stays dim and quiet.
Active
Shimmer · actively executing right now
Waiting
Amber · alive but not progressing
Error
Needs attention. Red, static, no animation.
Done
Green · stays visible until you close the popover — closing is your acknowledgment.

Active vs. Waiting — Three Approaches

Each dot below is live. The table documents why we chose what we chose.

Variation A

Active
Waiting
+Zero distraction. Instantly readable.
+Works with Reduce Motion on.
–Amber universally signals caution — could create anxiety.
–No motion means active looks the same as idle at a glance.

Variation B

Active — fast pulse
Waiting — slow pulse
+Speed communicates urgency intuitively.
+Feels alive and responsive.
–Two variables changing simultaneously (color + speed) increases cognitive load.
–Fast pulse can be distracting in peripheral vision all day.
Recommended Applied to prototype ↑

Variation C

Active — shimmer
Waiting — amber, static
+Motion and color are separated — each carries one signal only.
+Amber static reads as “held up” not “broken”. Shimmer is subtle enough for all-day use.
–Shimmer and amber are two different visual languages used simultaneously.
–Requires a moment to learn.

Our recommendation: Variation C. Motion belongs to work in progress. Color belongs to exceptions. Keeping them separate means each signal stays clean. Amber static for waiting maps to the universal meaning of amber in hardware LEDs — not an error, but not moving either.

How it was designed

Borrowed, not invented

Same visual grammar as Ethernet LEDs and the macOS camera indicator. Zero new concepts to learn.

Motion = state. Color = exception.

White dots handle 90% of cases. Color only fires for error and completion.

Hardware and software share one language.

The same dot pill lives in the SD card slot when the lid is closed.

Prior art — why this hasn’t been built yet

Every existing tool leaves the same gap.

OpenAI Codex App

First party · macOS + Windows · Feb 2026

Built specifically for parallel agent management. Sessions shown as a list — name, status, elapsed time. Requires the app to be open to check status.

parallel sessions task list UI no ambient awareness requires app open

OpenCode

Open source · TUI terminal · 162k GitHub stars

Rich terminal UI with session panel, token usage indicators, and SQLite-backed persistent sessions. Dual-agent architecture separates Plan from Build. No desktop ambient layer.

rich session panel token usage visible terminal only no ambient indicator

Dropbox

macOS menu bar · sync status

Single icon changes appearance per sync state. Animated arrows = syncing. Click opens a popover. Uses the icon itself as the sole state carrier — no pill, no count. Only ever one state at a time.

single icon clear states popover on click one state only no parallel sessions

macOS native dots

Apple HIG · camera · mic · location

Orange dot = mic. Green dot = camera. Single-purpose, single-instance. No grouping, no count, no parallel state. The design language we are extending — but it breaks at more than one concurrent instance.

instantly understood color = exception single instance only cannot show n parallel sessions

No ambient layer

Every competing tool requires its host environment open to check status. Close the app, lose visibility.

No parallel state

No competitor shows n parallel agent states in a single compact widget simultaneously.

No hardware surface

No product extends awareness to a physical surface. The SD slot LED row is completely unoccupied design space.

The Session Indicator is the only design that addresses all three gaps. Ambient. Parallel. Dual-surface. No competitor is within two steps of this.
